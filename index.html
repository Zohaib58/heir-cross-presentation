01 / Motivation

Why compiled regions?

The original HEIR-generated Python called CROSS public APIs. Simply wrapping that path in jax.jit did not give the desired improvement because array arithmetic remained mixed with Python-side orchestration and metadata handling.

What does JAX actually compile?

JAX traces a Python function containing supported array operations, lowers that computation through XLA, and compiles a reusable executable for the target device. It does not automatically compile arbitrary Python object handling or merge separately compiled calls.

Our goal: expose one connected raw-array function to JAX/XLA, rather than JIT-wrapping the original CROSS public-API orchestration.
01 · ORIGINAL EXECUTION

Public CROSS APIs

Object-oriented operation calls
rotated = ctx.he_rot[level, 1].rotate(ct)
product = ctx.ptct_mul[level].mul(rotated, pt)
result  = ctx.he_add[level].add(product, ct2)

These calls operate on CROSS ciphertext objects. Their surrounding Python can perform evaluator lookup, validations, metadata updates, and wrapper construction.

02 · INITIAL EXPERIMENT

Wrap the existing path in JIT?

Insufficient performance improvement
def original_model(ct, pt, ct2):
    ...  # Public API operations

compiled = jax.jit(original_model)

Simply applying JIT to this Python path did not achieve the desired optimization in our experiments. JAX cannot automatically turn arbitrary Python-side orchestration into efficient fused XLA computation.

03 · ARCHITECTURAL INSIGHT

Expose one raw-array computation

Our compiled-region approach
def raw_region(ct_array, args):
    a = rot._rotate_array(ct_array, ...)
    b = mul._mul_array(a, ...)
    c = add._add_array(b, ...)
    return c

Move reusable preparation and metadata bookkeeping offline. Give JAX/XLA a connected array computation to trace and compile together.

Our approach

Use OutlineCompiledRegions to select connected JaxiteWord operations; generate one raw-array function and separate offline metadata preparation. JAX requires a traceable function, not an MLIR region.

Online measurement boundaries

Warm encrypted computation

Time to execute the already-compiled encrypted neural network, including CPU-to-TPU dispatch and waiting for completion.

  1. Execute encrypted linear layers: rotations, ciphertext–plaintext multiplications, and additions.
  2. Compute square activations and add encrypted-model biases.
  3. Perform required CKKS transformations such as rescaling and relinearization.

Excludes input packing, encryption, decryption, output extraction, and offline preparation/compilation. Native uses mapping._compiled; HEIR uses plan.execute_raw. This is not a device-kernel-only measurement.

Client-to-client online latency

One complete inference request after one-time preparation

  1. Pack input: arrange the input into the encrypted model's required layout.
  2. Encode + encrypt: encode packed values into CKKS slots and encrypt them.
  3. Encrypted forward pass: execute the whole prepared network.
  4. Decrypt: decrypt the encrypted output into plaintext slots.
  5. Extract output: recover the model's output vector from decoded slots.

One-time initialization and compilation are not included. Independently measured per-stage medians are not additive.

Offline setup comparison

Offline preparation cost

One-time setup before warm online requests. Native and HEIR record different work.

Native CROSS
  1. Build mapping plan: trace, vectorize and pack the model computation.
  2. Materialize mapping: initialize required CKKS resources/constants and produce the compiled program.
HEIR Prepared
  1. Crypto initialization: configure context and generate public/evaluation keys.
  2. Preprocess model inputs and reusable plaintext/constants.
  3. Prepare the compiled plan, evaluators and templates; lower/compile the JAX raw-array function.

The reported HEIR preparation/compile duration covers the complete preparation function, not isolated XLA compiler time. First encryption and first raw execution were recorded separately.

Additional setup and comparison controls

Cryptographic settings. Ring-specific integer scale parameters are 1,152,763,181,911,621,633 (8K), 1,152,534,504,430,796,801 (16K), and 1,151,303,352,054,251,521 (32K), all near 260. σ ≈ 3.19; noise multiplier = 1; uniform-ternary secret; Barrett arithmetic; uint32 payloads; JAX x64 enabled.

Matched environment. Separate otherwise matching TPU VMs; same Python, JAX, jaxlib, libtpu, NumPy and SciPy versions, host CPU, memory and kernel.

Workloads. AlexNet-Tiny: input 3 × 16 × 16; LeNet: input 1 × 28 × 28. Both use batch 1, float32 inputs, square activations and four linear + four bias + three square operations. Paired inputs and packaged model weights were checked for correspondence.

Limitations. Native and HEIR use different CROSS revisions, BSGS choices and rescale placement. These timings compare full execution implementations—not an isolated effect of the outlining pass. One warmup + three synchronized repetitions.
